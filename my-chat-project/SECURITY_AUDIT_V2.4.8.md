# 拓界云客服 v2.4.8 安全复核

## 本次复核范围

- 历史模板授权模型和跨站令牌复用。
- 数据库迁移、参数化查询和租户隔离。
- 超级后台历史模板字段的 XSS 输出处理。
- 热路径查询数量、缓存和新增任务。

## 结论

- 历史记录只能由已认证租户保存设置、超级管理员明确勾选、当前配置迁移或平台强制迁移产生。
- 被拒绝的 Origin 请求与安全事件不会产生授权记录。
- 新增 SQL 全部使用位置参数；模板与租户 ID 先通过 UUID 校验，没有拼接用户输入。
- 超级后台模板名称和 Origin 继续通过统一 HTML 转义函数输出。
- 访客令牌同时绑定租户、会话、Origin 和模板 ID；同一租户的两个已批准站点也不能互相复用令牌。
- 全局模板状态仍具有最高优先级，`disabled` 模板不会因历史授权而恢复访问。
- 没有新增轮询或常驻定时查询；读取合并进已有配置缓存。

## 已执行验证

- Node.js 语法与前端 DOM/CSP 契约检查。
- 全部自动化回归测试，包括历史站点放行、陌生站点拒绝、跨站换新会话、SQL 参数化、XSS、安全告警和资源回归。
- Vite 生产构建，JavaScript 压缩和适度混淆，不生成 source map。
- npm 依赖审计。

## 边界说明

源码静态检查和自动化测试不能替代对真实部署环境的授权黑盒测试。云账号权限、WAF、数据库网络、Render/Netlify 配置和无线网络不在源码内，仍需按部署平台逐项核对。任何系统都不能承诺“绝对没有漏洞”；发现异常时应使用全局紧急停用模板，并保留审计证据。
